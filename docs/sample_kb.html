Summary:

Here's a few tips for using the KB generator.

  • If you were directed here from the first link on the sample page, you will see that it went to an explicit URL for this page. That's because the CSV file was directed to link that rule to this URL, specifically.
  • In most cases however, you will have a wiki or knowledgebase setup on which you create pages for each rule name. For those rules, you won't use the CSV file. Instead, you will let the script create a link based on the rule name. Usually, this would be something like "mywiki.com/rule-name"
  • If you want to use the same page for multiple rules, you can also use a parent page and let the script generate an anchor link, which is what happens for the remaining rules on the previous page. They all direct to "https://schvenn.github.io/AllKQLtoHTML/sample_kb.html#rule-name". Since the parent page exists, the redirection works. If the anchor doesn't exist however, you will be harmlessly directed to the page and the anchor will be ignored. This is a safe option.
  • Of course, you can also use the suffix portion, if necessary. That would be similar to the previous option, but perhaps you need a ".html" extension on the end. So, the generated link might instead look like "mywiki.com/rule-name.html"
  • The final tip I have regarding using this tool is to generate a search link, instead of a direct page link. If your knowledgebase was ServiceNow for example, you could let the script generate a link like this: "https://company.service-now.com/sp?id=search&spa=1&t=kb&q=some%20rule%20name", wherein the BaseURL would include everything up to the "q=" portion and the search query could be created for the remainder. In this case, you would use "html" for the separator option in the PSD1 configuration.
As you can see, there are many ways to make the link generation work, for nearly every environment.
