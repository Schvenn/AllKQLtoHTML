## Overview

AllKQLtoHTML reads Microsoft Sentinel Analytics Rule exports and generates a searchable single-page HTML report, along with a `report_navigator.json` file for use with the MITRE ATT&CK Navigator heatmap.

The generated webpage is designed to make large rule collections easier to review, search, document, and analyze. Features include:

* Rule statistics and severity breakdowns
* Interactive filtering by severity, rule state, template status, MITRE ATT&CK mappings, and text searches
* MITRE ATT&CK coverage visualization
* KQL syntax highlighting
* Query export and rule export capabilities
* One-click query copying
* Knowledgebase / Wiki integration
* Rule metadata inspection
* MITRE ATT&CK technique descriptions and direct links
* Rule merging and export consolidation
* Support for both Sentinel UI exports and Azure API exports
* MITRE ATT&CK Navigator layer generation

### Usage

```
AllKQLtoHTML <file1.json> <file2.json> <outfile.html> <-concat> <-merge> <-preserveids> <-createcsv> <-createlinks> <-usage> <-getazcommand> <-help>
```

| File    | Default Filename                    | Notes                                                         |
| ------- | ----------------------------------- | ------------------------------------------------------------- |
| File1   | Azure_Sentinel_analytics_rules.json | Default filename generated by the Sentinel UI export process. |
| Outfile | AllSentinelRules.html               | Output HTML report. Any filename may be supplied.             |
| File2   | All_Azure_Sentinel_rules.json       | Optional second file used with the `-merge` switch.           |

### Switches

| Switch          | Description                                                                                  |
| --------------- | -------------------------------------------------------------------------------------------- |
| `-concat`       | Combines multiple Sentinel ARM template exports into a single file before processing.        |
| `-merge`        | Merges two rule exports into a unified dataset.                                              |
| `-preserveids`  | Preserves original Sentinel GUIDs instead of generating new IDs.                             |
| `-createcsv`    | Generates a CSV file containing rule names and GUIDs for documentation and wiki integration. |
| `-createlinks`  | Uses the CSV file and PSD1 configuration to generate direct knowledgebase/playbook links.    |
| `-getazcommand` | Displays the Azure CLI command required to export rules from Azure Cloud Shell.              |
| `-usage`        | Displays usage information.                                                                  |
| `-help`         | Launches the built-in interactive help viewer.                                               |

## Azure Cloud Shell JSON Export (PowerShell Version)

If you wish to export rules directly from Microsoft Sentinel using Azure Cloud Shell, launch PowerShell from portal.azure.com and run the following command:

```
az sentinel alert-rule list --resource-group 'RG-<env>-<region>-<service>' --workspace-name 'LAW-<env>-<region>-<workload>' --subscription 'ffffffff-ffff-ffff-ffff-ffffffffffff' -o json > All_Azure_Sentinel_rules.json
```

To retrieve your Subscription ID:

```
az account show --query id -o tsv
```

To retrieve your Resource Group and Workspace names, navigate to the Sentinel Overview page.

Once identified, these values can be stored in the PSD1 configuration file for future use with the `-getazcommand` switch.

## Using the -merge Switch

If you provide the `-merge` switch, you should also provide a second JSON file. Without the switch, the second file is ignored.

The merge engine is designed to combine Sentinel UI exports (ARM templates) and Azure API exports into a single normalized rule set. Any combination of supported export types may be used.

When overlapping data exists, ARM template values are preferred where applicable because they typically contain richer Sentinel-specific configuration details.

The merge process also normalizes differing JSON structures automatically, allowing both export formats to be analyzed through the same reporting interface.

If more than two files must be merged, it is generally best to combine similar export types first and then perform the final merge using AllKQLtoHTML.

## Using the -concat Switch

Concatenation is different from merging.

The `-concat` feature is intended specifically for Sentinel UI exports that use ARM template format.

The Sentinel portal currently limits exports to approximately 50 rules at a time. To export larger environments:

1. Select and export the first batch of rules.
2. Move to the next page.
3. Export the next batch.
4. Continue until all rules have been exported.
5. Leave the original filename unchanged and allow Windows to append its standard numeric suffixes.

Example:

```
Azure_Sentinel_analytics_rules.json
Azure_Sentinel_analytics_rules (1).json
Azure_Sentinel_analytics_rules (2).json
```

Output:

```
Azure_Sentinel_analytics_rules_combined.json
```

AllKQLtoHTML automatically detects these files, combines them into a valid ARM template, and then continues processing normally.

## Additional Output Files

### report_navigator.json

A MITRE ATT&CK Navigator layer is generated automatically.

This file can be imported directly into the MITRE ATT&CK Navigator to visualize:

* ATT&CK technique coverage
* Rule density by technique
* Detection gaps
* Coverage overlap

Each technique includes metadata showing which Sentinel rules provide coverage.

### AllKQLtoHTML.csv

Generated when using `-createcsv`.

The CSV contains:

* Rule name
* Rule GUID
* Knowledgebase link field

This file serves as a convenient registry for documentation projects, playbooks, runbooks, and internal wiki integration.

## Built-In Help

The script includes a full-screen interactive help viewer that can be launched with:

```
AllKQLtoHTML -help
```

The help viewer supports:

* Scrollable content
* Table of contents navigation
* Keyboard navigation
* Built-in documentation for all switches and features

Additional details and examples are available directly within the help system.
